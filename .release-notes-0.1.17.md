## For you and your queue

* The recommendation server now seeds your radio with the exact track on the queue instead of guessing from the artist name, so the mix matches your genre and artists. Same artist, same energy, the way Spotify and SoundCloud radio actually works.
* The queue no longer stacks the same song in slowed or remix form. Each cut of a song can appear once, so the radio keeps its genre and stops repeating one track with different names.
* Trending now and Top chart show real YouTube Music charts for your region with iTunes and Last.fm fallbacks, and the shipped defaults no longer pin Russia on new installs. Existing installs move to the detected region once.

## Self update

* Riff Rust now updates itself instantly like OBS: every launch checks our own releases on GitHub and silently downloads and installs a newer build, then relaunches on its own. If you are offline the app carries on and tries again the next time it starts.
* Every self update is hashed and verified before it installs.

## Player fixes

* Playback errors show a short readable message in the toast instead of one clipped line, so you can always tell what failed.
* The stream recovery path now actually runs, so a track that fails to load gets a real retry instead of ending in a dead player.
* Interface opacity never drops surfaces below a readable floor. Tiles, rows, menus and cards keep a readable scrim at any setting, so the background never washes the interface out.
* The sidebar stays a solid dark slab over background artwork, so it no longer takes on color from it.

## About and identity

* The about section shows the current app icon and the name Riff Rust, made by ziyyhhk & rootless.
* The support card reads Support me with a note about sharing the project, and the Discord link opens the Discord app when it is installed or the browser otherwise.
* Discord activity now carries the name Riff Rust.

## Responsiveness

* Hover, scroll, click and the settings panel now stay locked at 60 fps. Every frame composites on the GPU with CPU rasterization, so a full window frame stays under 17 ms instead of costing 50 to 60 ms and dropping to about 20 fps.
* The background video pauses when the window is minimised, unfocused, hidden, or when animations are off, and resumes the moment you come back. The last frame stays on screen as a still, and idle CPU with a static background sits near one percent of a core.
* Opening settings is faster: each setting row is measured once instead of five times, which cut roughly 130 ms from the first paint.

## Settings

* The settings panel is fully opaque above every layer, so scrolling never washes it out.
* The gear always opens on Interface, and each category opens only its own section.
* Custom banner and profile picture choices work, and `.jfif` is accepted alongside the usual image formats.
* Settings writes are flushed to disk on quit, and the tray quit path and the close button flush the storage map synchronously, so toggles stick across restarts.
* Dialogs opened from settings, including the clear cache confirmation, render above the panel instead of behind it.

## Discord presence

* Presence shows up at startup: the browsing card appears within a few seconds of opening the app and refreshes while you browse, instead of waiting for the first track.
* Browsing and search presence uses the Riff icon instead of a wordmark, so the card matches the app icon.
* The app reports connected only after Discord accepts both the handshake and the activity. A rejected activity flips the indicator back to disconnected and logs the reason.
* Presence moves through one polling thread that writes every track change and browse update immediately, and sends the activity again once Discord reports READY.

## Memory and CPU

* Idle memory measures about 63 MB in Task Manager style measurement, and playback stays far below the Electron build.
* Artwork on lists lazy loads, so artwork only decodes when it is about to be seen and the player stays lighter.
* WebView2 runs in low memory mode with a low memory usage target, and the host is limited to a single renderer process.
* Frames composite on the GPU while raster stays on the CPU, which keeps the renderer near 65 MB and the whole window at 60 fps.
* Heavy blurred background artwork and ambient blobs pause when the window is blurred or hidden.
* Decorative animations stop while nothing is playing and resume the moment playback starts, which took idle CPU from about twelve percent of a core to about one percent.

## Appearance

* The window and taskbar icon is the transparent emblem, with the black corners gone.
