## Riff Rust 0.1.20

Import any music file. The Create menu now has Import your music and it takes anything. mp4, mkv, mov, wma, aiff, even 3gp. If ffmpeg can read it, Riff can play it, converted to mp3 on import with the original title and artist where the file has tags.

Headset disconnect pause. When your headset drops off the audio output list, Riff pauses instead of playing into your speakers. Fixed at the device list level, works for Bluetooth dropouts and USB unplugs.

Gapless handoff. When the next track is a local cached file, the handoff is armed 250 ms before the end of the current track, so there is no silence between consecutive local songs. Shuffled streams still go through the normal resolve path.

I'm Feeling Lucky. A clover button next to Create in the library header. One tap and Riff builds a fresh queue from your favorites, history and daily mixes.

Mini player button fixed. Pressing the square inside the square button in the title bar no longer freezes the window. It now arms the compact layout before the native call returns, debounces resize handling, and the button works every time.

App icons replaced. The crab is gone. Every brand mark in the app now uses the new scalloped R emblem, from the window icon to the taskbar, the tray, the about screen and the welcome screen. Theme adaptive where the old one was adaptive.

Album tracks load now. Opening an album fetches its full track list from Deezer and resolves playback through YouTube Music search. No more empty album pages.

Lyrics are more reliable. Matching now retries without duration, tries every candidate instead of only the top scorer, and the duration penalty is lighter. Artist pages show the current track cover when no artist photo exists.

Collapsed library rail works. The Home icon no longer breaks when a custom icon file goes missing. It falls back to the built in emblem. The rail also scrolls horizontally when the buttons do not fit.

Queue is deduplicated. The same track can no longer appear twice in the queue.

Playback stability on first play of a brand new YouTube track is still limited by YouTube's own throttle and can take a few seconds before audio starts. Cached tracks are instant. 0.1.19 shipped with cache repair and this continues that work.

Memory use is the same as 0.1.18 and 0.1.19 measured the same way. Whole process tree settles around 170 to 210 MB after a minute, main process about 36 to 40 MB. The claim this app can run in 40 MB is false and this release does not make it true. Anyone promising under 40 MB for a WebView2 app is measuring something else.

Installer is unsigned current user, per the same NSIS setup as before. Updates pull automatically through the in app updater.
